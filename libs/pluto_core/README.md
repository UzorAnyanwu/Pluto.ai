# libs/pluto_core

Shared Python package for every backend service: SQLAlchemy models (the full schema from
[`docs/architecture/02-data-model.md`](../../docs/architecture/02-data-model.md)), the RLS-aware
async session/tenant-context machinery, Alembic migrations, and security primitives (JWT, password
hashing, refresh tokens). `services/api-core` depends on this as a local editable package; any
future service that touches the database (`workers`, `ai-engine`) will too.

## Layout

```
pluto_core/
  config.py          Shared Settings (env-driven), read by every service the same way
  db/
    base.py            Declarative Base, mixins, TenantContext, get_session()/session_scope()
    enums.py            Every StrEnum backing a Postgres native ENUM column
    uuid7.py             RFC 9562 UUIDv7 generation for all tenant-owned primary keys
    models/              One module per domain area (tenancy, crm, scheduling, ai_agent, ...)
  security/
    jwt.py               RS256 access token issuance/verification
    passwords.py          Argon2id hashing
    refresh_tokens.py      Opaque refresh token generation/hashing
migrations/
  env.py                Alembic environment — reads MIGRATION_DATABASE_URL, not DATABASE_URL
  rls_helpers.py          enable_tenant_rls()/disable_tenant_rls() + the canonical TENANT_TABLES list
  versions/
    ..._initial_schema.py                    Autogenerated from the models above
    ..._row_level_security_and_grants.py      Hand-written: RLS policies, pluto_app grants, the
                                                auth_resolve_business_by_email() login bypass
```

## Local setup

```bash
# 1. Start Postgres (with pgvector) + Redis. Either:
docker compose -f ../../infra/docker/docker-compose.yml up -d
#   ...or, on a machine without Docker, install Postgres 16 + the pgvector extension natively
#   and run ../../scripts/bootstrap_local_db.sh (that's what this repo's own dev environment
#   used to build and validate this package — see PROJECT_STATUS.md).

# 2. Bootstrap the database + least-privilege app role (if not using docker-compose's init script)
../../scripts/bootstrap_local_db.sh

# 3. Install this package (editable) into a venv
python3 -m venv ../../.venv && source ../../.venv/bin/activate
pip install -e .

# 4. Apply migrations
export MIGRATION_DATABASE_URL="postgresql+psycopg://<migration-role>@localhost:5432/pluto_ai_dev"
alembic upgrade head
```

## Why RLS is enforced here, not just documented

Every tenant-owned table has a Postgres Row-Level Security policy (see `migrations/rls_helpers.py`
and the `row_level_security_and_grants` migration) tying visible rows to
`current_setting('app.current_tenant')`, which `db/base.py`'s `get_session()`/`session_scope()`
sets via `SET LOCAL` at the start of every transaction from the request-scoped `TenantContext`.
This means a missing `WHERE business_id = ...` in application code cannot leak cross-tenant data —
the database refuses the rows. This is tested directly (not just asserted) in
`services/api-core/tests/test_rls_isolation.py`, which registers two tenants and proves the ORM
session for one cannot see, and cannot write into, the other's rows.
